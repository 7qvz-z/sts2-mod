# 仕様書: 敵ステータス倍率 MOD(Slay the Spire 2 / Steam ワークショップ用)

> MOD 名: Spire Scaler(ID: SpireScaler)。アイコン・説明文は後で決める
> 対象: Slay the Spire 2(アーリーアクセス、Godot 4.5 C# 製)
> このファイルは Claude Code に渡して実装を進めるための仕様書。

## 1. 目的
敵の HP と攻撃力(ダメージ数値)の倍率を、プレイヤーが自由に変えられるようにする。難易度調整用。

## 2. 機能一覧

### 2.1 倍率設定
- HP 倍率と攻撃力倍率は **別々** に設定する。
- 攻撃力倍率は **ダメージ数値のみ** に掛ける(攻撃回数、毒などのデバフ量、ブロック量には掛けない)。
- 設定は **層ごと** に変えられる。「層」は **幕(Act)** 単位とする(階層 Floor 単位ではない)。
- 設定は **敵の種類別**(通常敵 / エリート / ボス)に分けられる。
- 入力方法は **スライダー** と **数値入力** の両方。

### 2.2 倍率の範囲
| モード | 範囲 |
|---|---|
| 通常モード | 1〜10 倍 |
| 詳細設定オン | 0〜100 倍 |

- 「詳細設定」はオン/オフの設定項目。
- **詳細設定をオフにしたとき、設定値を全部リセット(1.0 倍)する。**

### 2.3 計算ルール
- 小数が出たら **切り上げ**。
- 0 倍のとき:
  - HP は **最小値 1**。HP 倍率が 0 のときだけ、敵はブロックを持たない(ブロックを 0 にする)。HP 倍率が 0 以外のときは、ブロック量に倍率を掛けない。
  - 攻撃力 0 倍はダメージ 0。
- 召喚された敵・分裂した敵にも倍率を **掛ける**。
- 同じ敵に倍率が二重に掛からないようにする(適用済みの印を付ける)。

### 2.4 反映タイミング
- 倍率の変更は **次の戦闘から** 反映する。戦闘中の敵には反映しない。

### 2.5 プリセット
- 各プレイヤーが、自分の設定値をプリセットとして **保存・読み込み** できる。
- プリセットは自分専用の保存ファイルに書く(ゲーム本体のデータは書き換えない)。
- 設定・プリセットの保存先はユーザーデータフォルダ(`user://`)とする。`mods/` フォルダ内の `.json` はすべて MOD のマニフェストとして読まれるため、そこには置かない。

### 2.9 前提 MOD
- 設定画面には **BaseLib** の設定機能(`SimpleModConfig`)を使う。BaseLib を前提 MOD とし、マニフェストの `dependencies` に `BaseLib` を入れる。

### 2.6 リセットボタン
- 全ての倍率を 1.0 倍に戻す。

### 2.7 倍率表示
- 戦闘中に「HP×○ / 攻撃×○」を表示する。
- この表示は **オン/オフ設定** にする。

### 2.8 対応言語
- 日本語、English、简体中文、한국어

## 3. マルチプレイ
- 使う設定値は **ホストの値**。参加者の値は使わない。
- 倍率の設定は **ゲーム開始前に固定** する(ゲーム中は変更不可)。
- **全員が MOD を導入していることが前提。** 導入していない人(または MOD のバージョンが違う人)がいる場合は **マッチングできない**。
- マッチングできない場合は、理由が分かるメッセージを表示する。
  - ゲーム本体が参加時に MOD 一覧(MOD 名+バージョン)を照合し、不一致なら ModMismatch として参加を拒否し、足りない MOD 名をポップアップ表示する。このため、マニフェストを `affects_gameplay: true` にし、変更のたびに `version` を上げれば、未導入・バージョン違いは自動的にはじかれる。
  - ホストの値は、自作のネットメッセージ(`INetMessage`)で参加者に送る。

## 4. 他 MOD との互換性(競合しにくい作り方)
1. 元のコードを置き換えず、元の処理の **後から** 倍率を掛ける(Harmony の Postfix など)。元の処理を丸ごと上書きする方式は使わない。
2. 倍率を掛けるのは、他の MOD が敵の数値を変えた **後**(戦闘開始時の最後)にする。他 MOD が追加した敵にも効くようにする。
3. 同じ敵への二重適用を防ぐ。
4. MOD ID、パッチ ID、設定ファイル名、保存ファイルは **自分専用の名前** にして被らないようにする。
5. ゲームのデータファイルは書き換えない。

## 5. 未決定事項
- MOD のアイコン、説明文(名前は Spire Scaler に決定)
- 周回・アセンション(難易度)がある場合の層の扱い
- 小数の切り上げを、他の倍率(弱体・筋力など)と合わせた最終値で行うか、この MOD の掛け算の直後で行うか(ゲーム本体は最終値を切り捨てる)
- 戦闘中に HP を再設定する敵(孵化・復活・分節など)を倍率の対象に含めるか
- ゲームの更新で動かなくなったときの対応方針
- 倍率を変えた状態での実績・スコアの扱い(ゲーム側の仕様を要確認)

## 6. 実装前に調べること(調査済み: 2026-10-29)
詳細は調査結果ドキュメント「StS2 敵倍率MOD 第6章 調査結果」(https://claude.ai/artifact/8zJCKManqceNhujCrkYidJ)を参照。
- StS2 の MOD の作り方: `mods/<ID>/` に `<ID>.json`(マニフェスト)・`<ID>.dll`・`<ID>.pck` を置く。公式ローダーが `[ModInitializer]` を呼ぶ。.NET 9 / Godot 4.5.1。
- パッチ方式: Harmony が使える(ゲームに同梱)。公開 MOD の多くが使用。
- 敵の HP: `CombatState.CreateCreature` の Postfix で掛ける。ダメージ: `Hook.ModifyDamage`(攻撃予告の表示も同じ処理を通る)。
- 召喚・分裂: `CreatureCmd.Add` も `CombatState.CreateCreature` を通るので同じ場所で掛かる。戦闘中に HP を再設定する一部の敵は `Creature.ScaleHpForMultiplayer` も対象にするか要検討。
- マルチプレイ時の MOD 確認: ゲーム本体の参加処理(`JoinFlow`)が MOD 名+バージョンを照合する(3章参照)。
- ワークショップ: 公式ツール megacrit/sts2-mod-uploader で `ModUploader.exe upload -w <フォルダ>`。
- 設定画面: 公式 API はない。BaseLib の設定機能を使う(2.9 参照)。
- 実装前の確認: 手元のゲームの `release_info.json` のバージョンを控え、`sts2.dll` を ILSpy 等で開いて上記のメソッド名が残っているか確かめる(調査は v0.103 前後のコードで行ったため)。
